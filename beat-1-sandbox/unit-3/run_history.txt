Why the disagreements

The eval fails on pkg-14 and pkg-20 for two different reasons: the rubric is too strict on pkg-14 and has no check for the thread and policy on pkg-20. 


What went wrong

pkg-14 (gold accept, we reject on scope, changes and test). The plan is honest and well grounded. The gold note says "ready as scoped".
- Scope and changes: the plan names the area ("client attach/reattach path in zellij-server", zellij-client's terminal query issuance) and says the exact functions will be pinned after tracing. Our rubric reads "names each file" literally, so this fails.
- Test: the plan re-runs the repro loop (5 SSH reattach cycles with no rgb: strings). It adds no new test, because SSH and terminal behaviour can't easily be unit-tested.
- Same pattern in calib-01: its gold note accepts a manual repro re-run, "with the color flip as the observable". Our "must add a test" rule would reject it. That contradicts the gold labels.
- calib-04 supports the same fix: it is rejected because the test plan is "run the full test suite" with no observable outcome for the fix.

pkg-20 (gold reject, we accept). The plan is excellent and follows the maintainer's direction. The gold note says it is rejected because the comment has no AI-use disclosure, and the repo policy requires disclosing all AI usage. The notes also say every package is treated as AI-assisted work. The rubric has no check that reads the repo's policy or the thread. pkg-04 is the other thread-convention case, rejected because its comment never engages the owner's direction.

Rubric changes

1. scope and changes: replace "names each file" with "names each file or the specific module, component or code path to be changed". Keep the required not-touching statement and the reasons. Add that an honest "exact functions to be pinned after tracing" is acceptable when the area is bounded. A vague "the codebase" or "the parser" still fails.
2. test: replace "adds a test" with "has a decisive test". It passes if the plan adds an automated test, or, when automation isn't practical, gives a repeatable check taken from the repro steps with an observable pass result (an output, an exit code or a color change). It fails on "run existing tests", "verify it works" or no test at all. This keeps your intent but matches calib-01, pkg-14 and calib-04.
3. New required comms check:
   - Evidence: the plan comment (and plan) read against Thread highlights and the repo-facts contribution policy.
   - Pass: the comment engages what the maintainer or thread asked for, and does not duplicate someone else's claimed effort. If the policy requires AI-use disclosure that covers the comment or plan, the comment discloses it. A policy that requires disclosure only in the PR (as in pkg-09) doesn't fail the comment.
   - Fail: the comment ignores an explicit maintainer direction (pkg-04), or omits a required AI disclosure (pkg-20).
4. diagnosis: no change beyond the contradiction clause I added earlier.
5. Verdict rule: accept only if all five checks pass, and unclear counts as fail.

Evidence-guide changes

- Test plan: match the new test check. Use calib-01 (manual repro with an observable result) and pkg-14 (repro loop) as passes, and calib-04 ("run the full suite") as a fail.
- Scope and Executability: add the "area or file" rule, with pkg-14 as the example.
- Comms: promote it from "not graded" to the evidence source for the new comms check. Add a step to read the Repo facts policy line first and note who the disclosure applies to (comments, PRs, or all AI use). Add pkg-20 (fail), pkg-03 (passes, it discloses AI use) and pkg-04 (fail, ignores the owner's direction).
- Package layout note: say that "AI-assisted" is assumed for every package, so a required disclosure always applies.

Procedure changes

- Update the four conditions in Check execution and add comms as the fifth check in the order, plus the matching Evidence gathering step.
- Note that all five checks must pass, and that any failing check names the deciding quote.
- Change the "adds a test" wording in the Test step to the decisive-test rule.

Verification and risks

- Re-run the eval after the edits. Target at least 19/20 (pkg-14 and pkg-20 both fixed) with no new misses, in particular calib-01, pkg-03 and pkg-09.
- Run it twice to check for variation, since the grader is a model.
- Risk: loosening test could let a weak manual-only plan through. The "observable pass result tied to the repro" requirement is what holds the line, and calib-04 is the check for that.
- Each time you edit the rubric, evidence guide or procedure, copy them to ~/.claude/skills/plan-check/ before running. The eval reads the installed copy.
