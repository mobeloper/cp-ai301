# Rubric: is this plan ready to post and build from?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| diagnosis | The plan's cause statement (`### Diagnosis` or `Cause:`) read against the issue title and body and the `## Repro evidence` block (live: the student's posted repro comment and the issue thread). See "Diagnosis and grounding" in `references/evidence-guide.md`. | Passes if the plan states what causes the bug AND cites evidence supporting that cause (a repro step, output, traceback, or code location), AND the diagnosis is relevant to the issue title (it explains the behavior the title names). Fails if no cause is stated, the cause is asserted with no supporting evidence, the cause contradicts a fact in the repro evidence, or it addresses a different problem than the issue title. | required |
| scope | The plan's in-scope / not-in-scope statements (`### Scope`, or `In:` / `Out:`) and the files or areas it names. See "Scope" in `references/evidence-guide.md`. | Passes if the plan names each file it will change, or, where exact files are not yet known, the specific module, component, or code path (a bounded area a stranger could locate; an honest "exact functions to be pinned after tracing" is fine); says what it will not touch; and gives the reason for the changes (what they are for). Fails if the change location is unnamed or unbounded ("the codebase", "the parser"), there is no not-touching statement, or no reasoning is given. | required |
| changes | The plan's files and steps (`### Files` and `### Approach`, `### Changes`, or `Change:`): each file or area, why it is modified, and any file added or deleted. See "Executability" in `references/evidence-guide.md`. | Passes if the plan says which files or areas are modified and why; any added or deleted file is explicitly justified; and the change is minimal (the described work plausibly stays under 500 lines changed). Fails if a modified file or area has no stated reason, an addition or deletion is unjustified, or the described change is a large rewrite (over 500 lines). | required |
| test | The plan's test section (`### Test plan` or `Test:`) and any test-adding step in the changes, read against the repro evidence's steps and Expected/Actual. See "Test plan" in `references/evidence-guide.md`. | Passes if the plan has a decisive test: it adds an automated test (a new or extended test case, naming where it goes), OR, when automation is not practical, it gives a repeatable check taken from the repro steps with an observable pass result (an output, exit code, or visible change that would differ on the unfixed code). Fails if it only says to run the existing or full test suite, to "verify it works", or names no test. | required |
| comms | The `## Candidate plan comment` (live: the draft comment) read against `## Thread highlights` and the `## Repo facts` contribution policy line. See "Comms" in `references/evidence-guide.md`. | Passes if the comment engages what maintainers asked for or settled in the thread and does not duplicate someone else's claimed effort, AND, when the contribution policy requires AI-use disclosure that covers the comment or plan (or all AI use), the comment states it. Treat every plan as AI-assisted. A policy that requires disclosure only in the pull request does not fail the comment. Fails if the comment ignores an explicit maintainer direction or a claimed effort, or omits a required disclosure. | required |

## Verdict rule

Ready (`accept`) if every required check passes. If any required check
fails, the verdict is `reject`. `unclear` counts as fail. There are no
preferred checks, so nothing else changes the verdict.
